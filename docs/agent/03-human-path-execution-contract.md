# Mira：逐步可见的信息路径契约

> 状态：最高优先级设计约束。任何 Agent、Runtime、工具或鼠标系统的修改必须符合本契约。

## 目标

Mira 的体验应当像一个人通过应用界面逐步查找和操作信息。Agent 不得在任务开始时预先得到最终答案；它只能在每一个已完成操作之后，获得该步骤实际抵达的信息，并据此决定下一步。

这不是固定流程。Runtime 不决定工具顺序；唯一 Agent 根据用户目标、操作知识和当前工具结果自主决策。

## 三层模型

| 层 | 责任 | 不负责什么 |
| --- | --- | --- |
| Agent | 根据已经观察到的页面事实决定是否观察、对哪个组件做什么动作、下一步做什么。 | 不得直接读取项目数据或空间坐标。 |
| 页面观察 | 唯一向 Agent 返回页面语义：可见文本、可见目录条目、按钮、当前页面和滚动状态。 | 不得返回屏幕外或尚未抵达的内容。 |
| 组件位置解析层 | 向鼠标动作系统返回当前可操作区域的中心点、滚动条位置、当前可见条目的位置。 | 不得向 Agent 返回目录内容、隐藏条目、总数或正文。 |
| 鼠标动作系统 | 使用空间定位结果表演并驱动移动、点击、滚动、输入等页面操作。 | 不决定业务目标。 |

对于现有页面中的操作，不设会直接读取“目录”“分集”“搜索结果”的领域 UI 工具。`page.inspect`、组件注册和 `ui.actAndObserve` 是完整的通用 UI 操作闭环；鼠标动作不是业务结论，页面观察才是唯一的页面语义来源。

空间定位结果属于执行上下文，不属于 Agent 认知上下文。Agent 说“滚动目录”后，Runtime 才可从组件注册/位置解析层取得当前目录中心并交给鼠标；Agent 不需要、也不应看到像素坐标。只有动作完成后的 `page.inspect` 能把新页面内容送回 Agent。

## 强制执行时序

```text
用户请求
  → Agent 创建任务、叙述“我看一下”
  → Agent 请求操作知识 + 当前页面观察
  → Runtime 执行并记录工具状态
  → Agent 根据返回结果选择一个真实页面组件和通用鼠标动作
  → 鼠标完成该组件上的页面动作
  → 页面状态更新，再由 page.inspect 返回本步骤可见事实
  → 结果进入下一轮 Agent 上下文
  → Agent 决定继续、追问、报告或完成任务
```

工具状态为 `queued → running → succeeded | failed | cancelled`。同一任务同一时刻只允许一个模型轮次；工具完成才可唤醒下一轮。

## 验收示例：查询剧本有几集

| 轮次 | Agent 能知道的事实 | 可选行为 | 该轮新增信息 |
| --- | --- | --- | --- |
| 1 | 用户问“剧本有几集” | 查询操作知识 + 观察当前页面 | 操作路径；剧本是否打开 |
| 2 | 观察到剧本未打开和入口 | 对 `script-bible-toggle` 执行 `mouse.click` | 剧本面板已打开，目录按钮可用 |
| 3 | 观察到目录按钮 | 对 `script.toc.open` 执行 `mouse.click` | 当前可见目录条目、是否到达底部 |
| 4+ | 目录尚未到底 | 对 `script.toc.list` 执行 `mouse.scroll` | 滚动后的可见条目与位置 |
| 最后 | 已获得足够目录证据 | 回答并显式完成 | 结论及其证据范围 |

目录尚未打开时，`page.inspect` 不得返回目录内容；`mouse.scroll` 必须按给定方向和距离改变同一可见滚动容器；不得直接将目录跳至结尾后把完整计数交给 Agent。

## 目录位置解析规范

目录位置解析不是工具，不向 Agent 输出内容；它是鼠标执行器使用的内部适配层。它可提供：

```ts
type DirectorySpatialMap = {
  viewportCenter: { x: number; y: number };
  viewportTop: { x: number; y: number };
  viewportBottom: { x: number; y: number };
  scrollbar: {
    trackTop: { x: number; y: number };
    trackBottom: { x: number; y: number };
    thumbCenter: { x: number; y: number };
  };
  visibleEntryCenters: Record<string, { x: number; y: number }>;
};
```

此对象只发送给动作系统。当前未显示的剧集没有有效屏幕坐标；如果 Agent 未从 `page.inspect` 看见“第 5 集”，目录工具不得用后台索引给鼠标提供“第 5 集”的隐藏位置。Agent 只能先决定滚动，等新的页面观察显示第 5 集，再决定点击它。

## 每次方案或实现前的检查

1. 页面语义是否只经 `page.inspect` 进入 Agent 上下文？
2. 位置数据是否只流向鼠标动作系统？
3. 每次动作后是否重新观察页面才开始下一轮 Agent 决策？
4. Runtime、工具是否保持执行职责，而没有代替 Agent 选择下一步？

任何答案为“否”时，先修订方案，不能继续实现。

## 证据规则

- “最后一项是第 58 集”只证明最后编号为 58。
- 如果目录存在第 0 集、跳号或重复条目，不能以最后编号代表实际条目数。
- 若问题要求“总共多少集”，Agent 必须取得足以计数的目录证据，或诚实说明只能确认最后编号。

## 工具目录要求

工具管理页面应列出通用观察、知识与鼠标动作能力；组件注册页面应列出每个真实页面组件、其位置、允许动作和可见性。后续新增 UI 先注册真实组件，再接入这一套闭环，不新增绕过页面可见性的读取工具。
