# Mira Agent 架构总览

## 目标

Mira 是应用中唯一拥有自主决策循环的 Agent。用户提出目标后，Mira 自行申请所需上下文、建立任务、选择工具或专家能力，并根据工具结果继续下一轮，直到任务完成、受阻或需要用户确认。

## 基本原则

- Agent 只有一个；工具与专家不拥有自主循环。
- 对 UI 型任务，Agent 的项目事实只能来自用户此刻可见的页面；项目数据层只驱动界面渲染，不能直接作为 Agent 上下文。
- 每次界面动作都由 Agent 鼠标执行并反馈；动作完成后，再读取新的真实页面观察，而不是后台数据。
- 工具结果是下一轮 Agent 的上下文，不插入或篡改已经发出的模型请求。
- 每个任务独立运行；任务可以只读查询其他已发布任务的产物，但不能干扰它们。
- 文档与数据均应可序列化、可被 Git 版本管理，且不依赖具体渲染技术。

## 运行循环

```text
用户消息
  → Mira 生成叙述与工具请求
  → Runtime 校验并执行工具
  → 鼠标适配层执行可见 UI 动作
  → 工具返回结构化结果
  → Runtime 将结果加入下一轮上下文
  → Mira 决定继续、回答、受阻或请求确认
```

## 任务状态

| 状态 | 含义 |
| --- | --- |
| `running` | 有下一步可执行，或正在等待工具结果。 |
| `completed` | 已得到支持最终回答的证据，并已向用户交付结果。 |
| `blocked` | 完成目标所需的工具、数据或权限尚不存在。 |
| `needs_user_input` | 下一步必须由用户选择、补充或确认。 |
| `failed` | 执行发生非预期错误，且不能安全继续。 |

`completed` 不能仅由模型自行断言；Runtime 必须检查任务目标已被工具证据覆盖。
