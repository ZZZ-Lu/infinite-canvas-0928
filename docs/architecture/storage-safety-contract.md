# 当前存储机制保护契约

本契约保护已投入使用的路径，增加约束、故障回归及 CI，不迁移数据库，不改变用户数据格式。

## 唯一有效的主路径

App → src/db.ts → IndexedDB InfiniteCanvasDB / workspace。

项目目录及剧本：localStorage/script_projects；当前项目：current_project_id。卡片按 cards_<projectId> 保存，旧版未分项目数据为 cards；附属键为 _backup、_save_info。项目中保存的媒体是 Blob/File，blob URL 仅为可重建的运行时引用。Agent traces 为 agent_traces。

src/storage/cardRepository.ts、database.ts、status.ts、appStorage.ts 是另一套实现，目前未接入主卡片链路。禁止仅替换 import 就切换后端。草稿和 MCP 密钥另有数据库，其完整迁移/异常恢复尚不属于本轮测试覆盖范围。

## 不可破坏的行为

1. 读取异常、格式不兼容或已有记录异常缺失时，停止加载/自动初始化和覆盖，保留原数据并显示错误；null（确实无记录）与 []（用户清空）不能混同。
2. 不指定版本打开现有主数据库；不因为格式不兼容、升级阻塞或打开失败而删库重建、clear 整个仓库或自动降级。
3. 保存前捕获元数据快照、校验 ID、检查 blob URL 的二进制来源。不可用 JSON.stringify/parse 复制包含 Blob 的卡片；ID、世界坐标、原始文件和参考图必须往返保留。
4. 同项目写入串行。以事务 complete 为保存成功依据；单次 put success、队列已接收、UI 已更新均不等于提交完成。
5. 主记录、备份及保存信息在同一事务内写入；事务失败时原记录不能变，UI 不得报告保存成功，失败必须可重试且维持未保存保护。
6. 多页面以读取基线、本地快照、数据库当前值进行三方合并。无基线的旧页面不得盲写；本地未改字段不能抹掉其它页面修改。相同字段冲突仍采用现有提交顺序，不宣称具备协同编辑或冲突提示能力。
7. 重试继续使用首次尝试的基线和捕获快照，避免混入后来的对象突变或覆盖远端无关更新。
8. 保存空数组仍属于有效保存，但不能用它消灭已有非空备份；取消/切换项目后的迟到回调不得写入另一项目。
9. 项目切换前等待当前项目保存，失败就不切换；已有项目不因读取错误自动变成默认项目。正常编辑期间保存，离页 flush 只是尽力补救，不能当成唯一保障。
10. 删除必须限定项目，保留原数据备份及删除标记，拒绝旧页面复活已删除项目；恢复备份后应能继续保存。

项目目录和卡片分属 localStorage/IndexedDB，没有跨二者的统一原子事务；只有一份卡片回退备份，不是完整版本历史。浏览器持久化申请不是外部备份。这些边界不能在后续文档或 UI 中被描述成已解决。

## 自动验证

运行 `npm run test:storage`，再运行 `npm run lint`。测试使用 fake-indexeddb 的独立 IDBFactory，不读取真实浏览器数据库、不依赖网络或密钥。

| 范围 | 保护用例 |
| --- | --- |
| 保存归属 | 项目切换取消、迟到回调、快照捕获、同项目队列 |
| 原子性 | 成功请求后事务中止、配额不足同步故障、旧记录和备份不受失败写入影响 |
| 媒体 | 文件/原始文件/无损文件/嵌套参考图字节往返；拒绝无二进制的 blob URL |
| 多页面 | 增加卡片、不同字段合并、无基线盲写拒绝、失败重试后保留远端编辑 |
| 数据完整性 | 重复 ID 拒绝、异常记录拒绝、已有数据缺失时停止覆盖 |
| 恢复 | 清空保留备份、删除后旧页面不能覆盖、备份恢复、项目隔离 |
| 兼容性 | 未知数据库保留、高版本不降级、旧连接不被强制升级 |
| 接入契约 | App 保存入口固定为 db.ts；主后端不调用删库或全仓库清空 |

现有测试部分通过定位 App 调度代码执行真实调度逻辑；重构注释或函数位置时可能需要同步调整测试提取方式，不能因此跳过相关行为验证。模拟数据库不等于真实磁盘配额和浏览器退出测试。

## 持续集成与迁移门槛

.github/workflows/storage-safety.yml 在推送、PR 和手动触发时执行锁文件安装、存储测试、类型检查及生产构建。配置提交到 GitHub 后生效。若要阻止失败代码合并，需要仓库管理员在 main 分支规则中把 storage-safety 设置为必需检查并限制绕过；仅存在 workflow 文件不会自动开启分支保护。本轮未修改仓库远程设置。

数据库/键格式/保存入口改变前，先提交契约变更与迁移设计：识别旧格式 → 复制迁移 → 校验卡片数/ID/原始字节 → 完整事务提交 → 可回滚；保留旧数据直到迁移验证完成，并增加旧版、空项目、失败及中断重试用例。不得以放宽断言或吞掉异常作为通过检查的办法。

## 架构边界

本轮新增内容仅为测试、CI 和开发规范；未新增运行时状态、DOM 依赖或项目字段。业务模型与渲染适配器继续分离，后续 Canvas/WebGL 替换不应更改持久化格式。Blob 由 IndexedDB 结构化克隆保存，不能将其误认为直接 JSON 序列化即可保留二进制。
