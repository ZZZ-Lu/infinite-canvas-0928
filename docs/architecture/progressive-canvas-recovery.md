# 渐进加载与恢复

原则：用加载完成时间换取交互帧数。停止交互后的恢复起点仍为 300ms。

## 实现

- App 合并 300ms 窗口内的 `card-painted` 通知，交互期间继续延后全局刷新。单卡的加载状态通知仍即时接收。
- 中心优先挂载队列每批只加入一张卡片，经过两个 requestAnimationFrame 边界后再加入下一张。这是节流，不代表图片解码或 React 提交完成的确认。
- 提示词文字和面板装饰共享 `scheduleCanvasSurface` 队列。每两个帧边界最多执行一个绘制任务；拖动或缩放期间暂停。已经显示的位图继续保留，组件更新、卸载时取消旧任务。
- 缩略图写回在交互期间每 300ms 检查一次，候选参考卡列表通过 useMemo 避免无关更新重复扫描。

## 数据边界

新增队列仅存在于 `src/utils/canvasPerformance.ts` 的渲染模块内，不写入项目状态。业务模型、世界坐标、原始 AI 输入和项目序列化格式均未改变。DOM 属性只用于判断渲染器是否正在交互，不作为业务数据。后续替换为 WebGL 时，替换绘制适配器及调度入口即可。

## 验证与局限

类型检查、生产构建通过。`work/check-surface-queue.cjs` 验证逐帧执行、交互暂停与恢复、取消以及绘制异常后的后续任务恢复。

预览跨越远景阈值后，观察到挂载数量从 3 张补齐至 14 张，14 个文字 Canvas 均获得有效位图尺寸。该验证不等同于完整性能 A/B 测试，不据此承诺最低帧数。

单张卡片的 React 挂载或单个绘制任务仍不可抢占；这轮没有把整棵 App 的 React 更新彻底拆分。大量 allCards 数据更新、主题切换、图片解码仍可能产生长帧，后续应以新的长任务记录决定拆分位置。
