# 储存安全修复（基于 434e50f）

## 修复内容

- 自动保存捕获项目 ID 与卡片快照，清理时取消定时器；不再让旧空闲回调读取另一个项目的全局卡片。普通编辑防抖 500ms，连续编辑最长等待 2s，本地导入文件立即排队保存。
- 以 IndexedDB 事务 `complete` 为成功条件；中止、配额、连接或格式错误均向调用方返回失败。按项目串行写入，失败操作可重试，未完成或失败时提示离开风险。
- 使用现有数据库版本打开连接。没有兼容的 workspace 表时停止操作，禁止删除数据库、降级或强制升级。
- 每次写入在事务中读取最新记录，以本页最后提交的快照为基线合并实际修改；不同卡片和不同字段的修改保留，同字段冲突按提交顺序处理。本页没有读取过的现有项目禁止盲写。
- 读取失败或已知项目记录缺失时停止编辑和自动保存，不再把空状态当初始化信号。首次工作区及显式新建项目才创建初始卡片。损坏项目目录保留原文，不用默认目录覆盖。
- 非空旧记录与新记录在同一事务中保留备份；删除保留备份与删除标记，阻止旧页面复活项目。读取异常时可恢复备份。
- 导入卡片从创建时就包含原文件 Blob，避免只保存临时 blob URL。图片纹理加载失败移除失败对象，带退避最多尝试三次。

## 数据与渲染边界

沿用 InfiniteCanvasDB/workspace 的 cards_<projectId>，新增同表 `_save_info` 和 `_backup` 记录。项目目录和设置仍沿用 localStorage，本次未迁移或重构全部存储格式。

src/utils/storageMerge.ts 只处理普通元数据和不可变 Blob，不依赖 React、DOM 或 Canvas；src/db.ts 负责事务，App 负责订阅状态与显示错误。更换 Canvas/WebGL 渲染器不需要修改合并和事务逻辑。元数据可 JSON 序列化，二进制通过 IndexedDB 结构化克隆保存，JSON 导出仍需要单独编码 Blob。

## 验证

- `node tests/canvas-performance/check-storage-safety.cjs`：通过，覆盖旧回调取消、空项目/撤销、事务中止、跨页面合并、快照捕获、写入队列、Blob、备份/删除/恢复、不兼容版本保留、无强制升级、缺失保护、原始文件与图片重试。
- 独立原生浏览器两个标签页：A 新增、B 修改，刷新后两张卡片均存在，位置 42，1MiB Blob 尾部字节 123 保持；请求成功后注入事务中止时保存明确失败且旧提示词不变；切换后旧回调写入次数为 0。
- 独立源运行完整应用，首次初始化及刷新后卡片均恢复。
- `npm run lint`、`npm run build`、`git diff --check` 通过。构建保留已有大包体积提示。
- `check-card-mount-store.cjs` 通过。额外两项测试失败：`check-adaptive-recovery.cjs:5` 预期 idleFrames=0、实际 2；`check-bitmap-cache.cjs:9` 预期 undefined、实际缓存对象。对应源文件及这两项测试与 HEAD 相同，此次没有修改它们。

## 限制

同字段并发修改不提供交互式冲突选择；项目目录和设置仍有 localStorage 的容量和多页面覆盖边界。备份只有同库上一份非空记录，不是完整历史。整站数据被清理、浏览器存储损坏或磁盘故障可能同时影响主记录与备份。本次验证不证明历史实际丢库事件的底层原因，也不保证恢复已被删除的数据。浏览器持久化授权可申请，但不能强制授予。
